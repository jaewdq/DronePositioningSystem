# 드론 측위 시스템 설계서

지상 고정 LiDAR 2대만으로 비행 중인 드론의 3D 위치를 실시간 추정하는 **outside-in 측위 시스템**의 설계 근거와 결정 사항 정리.

실행 방법·현재 성능·알려진 문제는 [README](../README.md)에, 칼만필터 적용 구조는
[KALMAN_FILTER_DESIGN.md](KALMAN_FILTER_DESIGN.md)에 있다. 이 문서는 **왜 그렇게
설계했는가**만 다룬다.

> **한 줄 정의**: 팀마다 다른 기체를 **형상 무관하게** 측위한다.
>
> **데이터 흐름**: `LiDAR 2대 → 좌표변환·융합 → 전처리 → 탐지 → 연관 → 추적필터 → 위치출력 → 평가`
>
> **4개 설계 축**: ①어디서 보나 → ②어떻게 위치 뽑나 → ③무엇을·어떻게 평가하나 → ④실전 대비

## § 1. 센서 배치 (입력 품질)

**목적**: 드론이 필드 어디에 있든 충분한 점이 맞도록 센서를 배치.

| 항목 | 결정 | 근거 | 상태 |
|---|---|---|---|
| 센서 | Ouster OS1 **128ch × 2대** (남쪽은 OS1-SR) | 대회 지정 | **확정** |
| 높이 | **2.0m** | 목표 호버고도(2.0m)와 같게 두면 어느 거리에서든 시선각 0° → 좁은 수직FOV를 온전히 여유로 씀 | **확정** |
| 배치 | **ns (남북)** | 필드가 가로로 김(30×20) → 짧은 축이 최대거리 26m로 최소 → 밀도 최고 + 마주봐서 편향 상쇄 + 360° 수평 공짜 | **확정**(실측 검증 완료) |

### 임무구역 & 제약
- 임무구역: 30m(X) × 20m(Y), 중심 (15, 10)
- 금지구역(안전여유): 중심 기준 33×23m, 즉 `|x-15|<16.5 AND |y-10|<11.5` 내부에 LiDAR 설치 불가
- LiDAR 사양: 수평 360°/1024, 수직 **±21.2°/128ch**, 노이즈 σ=0.5cm, 10Hz
- 사거리는 변종별로 다름 — OS1 0.1~170m, OS1-SR 0.3~85m (10% 반사 기준 90m / 45m)

### 센서 변종 배분 (남 = SR)

두 변종의 차이는 **사거리뿐**이다. 수직FOV·채널·각분해능·정밀도가 동일하므로
배치 계산은 그대로 쓴다.

마커 4개 중 3개가 필드 남쪽 절반(y=4~12)에 있어 **북쪽 센서가 구조적으로 더 먼
거리를 담당**한다. 실측 최대 관측거리가 남 20.6m / 북 26.3m이므로, 사거리 여유가
적은 SR을 가까운 쪽(남)에 둔다 — 10% 반사 45m 대비 여유가 2.2배 대 1.7배.

### 높이 결정 (OS1 전환 후 재검토)

OS0-SR(±45.4°) 시절에는 바닥 시작점을 보기 위해 1.5m를 택했다. OS1은 수직FOV가
**절반 이하(±21.2°)**로 좁아져 전제가 바뀌었다.

| 높이 | 가장 가까운 지점(1.5m)에서의 고도 여유 |
|---|---|
| 2.0m (호버고도와 동일) | 시선각 0° → **±21.2° 전부 여유** → ±0.58m |
| 1.5m | 시선각 18.4° 소모 → 남는 여유 2.8° → ±0.07m |

호버고도와 센서높이를 **맞추면** `atan2(2.0−h, d) = 0°`이 되어 거리와 무관하게
수직FOV를 전부 여유로 쓴다. 좁은 FOV에서는 이 효과가 지배적이므로 2.0m가 확정.

대가: 지상(z≈0)의 드론이 FOV 밖으로 나간다 → 이착륙 구간 추적을 포기한다
(§3.2의 기준면 문제와 연결).

### 배치 비교 (검출 밀도 계산: 점수 ≈ 1600/거리²)
| 배치 | 위치 | union | 양쪽동시 | 최소점 | 최대거리 |
|---|---|---|---|---|---|
| **ns (남북)** | (15,21.5)+(15,-1.5) | 100% | 100% | **9.0** | **26.2m** |
| cross (동서) | (31.5,10)+(-1.5,10) | 100% | 100% | 8.6 | 33.0m |
| edge (동북) | (31.5,10)+(15,21.5) | 100% | 100% | 3.8 | 33.0m |
| diag (대각) | (-1.5,-1.5)+(31.5,21.5) | 100% | 96% | 5.1 | 38.1m |

**핵심 원리**: 360° 수평시야 → "드론 어디 있든 수평으론 잡힘" → 남는 변수는 **거리와 수직FOV뿐** → **거리 최소화 = 짧은 축(ns)** 이 정답.

### 이론적 순위: ns > cross > edge > diag
결정 3요소:
1. **거리→밀도** (지배적, 원거리 점 부족이 병목): 짧은 축 ns 최고
2. **커버리지**: ns/cross/edge 100%, diag 96%
3. **편향 상쇄 & 삼각측량**: 마주보기(ns/cross)는 근접면 편향 상쇄, 직교(edge)는 GDOP 유리하나 LiDAR는 range 직접측정이라 이점 감소 + 먼 구석 검출 약함

**실측 검증(ns)**: 검출률 99~100%, 경로점 7/7 검출. 이론 예측대로 동작.
diag/cross/edge는 실행하지 않았다 — ns가 기준을 충분히 만족해 비교 실익이 없었다.

## § 2. 측위 알고리즘 (점구름 → 위치)

**목적**: LiDAR 점을 처리해 드론 위치를 뽑고 시간축으로 잇는다. **탐지 후 추적(detection-then-track)** 방식(SLAM/모델피팅 아님).

| 단계 | 하는 일 | 현재 알고리즘 | 개선 여지 |
|---|---|---|---|
| **2.1 전처리** | 점 다듬기 | 좌표변환 → 신선도/동시성 검사 → 융합 → ROI(z-band 1~3m) | Voxel·SOR은 구현돼 있으나 비활성 |
| **2.2 탐지** | 드론 덩어리 찾기 | **DBSCAN**(eps 0.4, min_pts 2) + 크기 필터(2~400) | 예측 기반 클러스터링 |
| **2.3 융합** | 두 LiDAR 합치기 | 점 병합(early fusion, concatenate) | 센서별 갱신 시험 후 기각 → [KF 문서](KALMAN_FILTER_DESIGN.md) |
| **2.4 연관** | 어느 덩어리가 드론? | 최근접이웃(NN) + **적응형 게이트**(KF 공분산 비례, 상한 4m) | 클러터 생기면 **PDA + 마할라노비스 게이트** |
| **2.5 추적** | 매끄럽게 잇기 | 칼만필터(등속도, 6상태) + 코스팅(1.5s) → 5초 후 리셋 | 코너 지연 크면 **IMM(CV+CA)** |

### 지면제거 단계가 없는 이유

ROI의 z-band(1.0~3.0m)가 호버 고도만 통과시키므로 **바닥이 애초에 파이프라인에
들어오지 않는다.** RANSAC/높이컷 지면제거를 통째로 대체한 것으로, 이착륙·지상
구간 추적을 포기하는 대신 얻은 단순함이다.

이 결정에는 함정이 하나 있었다. ROI를 좁히면서 그 뒤에 있던 "점 10개 미만이면
버림" 방어 코드를 그대로 뒀는데, ROI 안에 드론밖에 없게 되자 그 문턱이 **드론 점
개수와 직접 비교**되어 원거리 검출을 대량으로 버렸다(검출률 37%). 문턱을
`min_pts`로 낮춰 해결. **설계를 바꾸면 그 설계에 딸린 상수도 같이 봐야 한다**는
교훈.

### 추적 필터 상세 (선형 KF, 등속도)
- 상태: `[x, y, z, vx, vy, vz]` (6차원)
- 예측: `x ← F·x` (F는 x+=v·dt), `P ← F·P·Fᵀ + Q`
- 보정: `y = z − H·x`, `K = P·Hᵀ·S⁻¹`, `x ← x + K·y` (측정은 위치만, H는 위치 3개 관측)
- 노이즈: Q(위치 5cm/속도 0.3), R(측정 15cm = 원시 0.5cm + 센트로이드 추정오차)
- 순서: **predict → 연관 → update** (연관을 예측 위치 기준으로 걸어야 1프레임 지연이 안 생김)
- ※ 운동·측정 모두 선형 → EKF가 아닌 **표준 칼만필터**

### 데이터 연관 robustness

- **적응형 게이트**: 게이트 폭을 KF 공분산에 비례해 넓힌다. 잘 추적 중이면 좁아
  클러터를 막고, 놓친 뒤에는 공분산이 커지며 자동으로 넓어져 재획득을 돕는다.
  상한 4m로 잘라 엉뚱한 클러스터를 붙잡는 것은 막는다.
- **home 씨딩**: KF를 (0,0,2.0)에 초기화 → 첫 검출부터 예측 기준이 있음
- **코스팅 → 리셋**: 1.5초까지는 예측만으로 발행, 5초를 넘으면 트랙을 버리고
  콜드스타트로 전환(오래된 예측에 게이트가 묶여 영영 못 붙잡는 것 방지)

**핵심 원리**: LiDAR는 위치만 주고 속도는 필터가 추정. 드론을 "떠 있는 컴팩트한 점 덩어리"로만 인식(형상 무시) → 형상 무관 & XY 정확, Z 약함.

## § 3. 기준점 & 평가 (설계자 = 나)

**대전제**: 팀마다 기체 형상이 다르고(50cm~1m, 사전 미지), **내가 시스템 설계자**다. "드론 위치"의 정의는 **내가 정하는 스펙**이며 반드시 **형상 무관**해야 한다.

### 3.1 기준점 정의 (스펙)
- **드론 위치 ≡ 포인트클라우드 센트로이드** (검출 클러스터의 기하 중심, median)
- 근거: 기체를 모르니 무게중심을 알 방법이 없음 → 관측점 중심이 유일하게 공정·재현 가능
- median을 쓰는 이유: 이상치 하나가 평균은 눈에 띄게 끌지만 median은 거의 못 움직임
- ns 마주보기 배치가 **양면 평균**으로 센트로이드를 진짜 기하중심에 근접시킴 (§1과 맞물림)
- ⚠️ **기체별 보정 오프셋 금지** — 형상 무관성이 깨짐

### 3.2 검증 기준 (외부 정답 아님)
- 시뮬의 PX4 위치는 **알고리즘 검증용 참값**일 뿐, 외부 규정 아님
- PX4 원점(base_link) ≠ 센트로이드 → 둘의 차이는 **정의 차이지 오차가 아님**
- 실측 Z 차이 **+0.18~0.26m**. x500은 `model.sdf`에 `<pose>0 0 .24>`로 정의되어
  착지 시 base_link가 지면 위 0.24m에 있는데, 그 값과 대체로 일치한다

**미결 항목 — 채점 기준면**: 이 오프셋을 대회에서는 알 수 없다(기체마다 다름).
두 방향이 있다.

- **(a) 절대고도로 채점** — "지면 위 몇 m". 오프셋 불필요. 기체별 착지 센트로이드
  높이 차이(대략 ±0.1m)가 그대로 오차에 들어감
- **(b) 패드 대비 상승고도** — 이륙 전 패드 위 센트로이드를 한 번 재고 `현재 − 기준선`.
  형상이 상쇄되고 참가팀 텔레메트리와 숫자가 맞음. **base_link 위치를 알 필요가 없다**
  (가정이 아니라 측정). 대가로 지상의 드론이 보여야 해서 ROI z-band를 낮춰야 하고,
  그러면 §1의 높이 결정과 충돌한다

→ **아직 정하지 않았다.** 정하기 전까지 보고되는 Z는 "월드 절대고도"다.

### 3.3 성능 지표 (절대오차 ❌)
- **정밀도(precision)**: 추정값 표준편차 — 얼마나 안 흔들리나 ← 핵심 성능
- **추종성**: 실제 궤적을 형태적으로 잘 따라가나
- **검출 안정성**: 검출률·미검출 구간
- 절대 오프셋은 "정의 차이"로 별도 표기, 성능 감점 아님

계통오차(bias)와 산포(std)를 반드시 나눠 본다. bias는 상수라 빼면 사라지지만
std는 못 없앤다 — **std가 실제 성능**이다. 실측 수직 bias +0.185m / std 0.017m.

### 3.4 좌표계·시간정렬 (계산 전제)
- 좌표계 일치: Gazebo world(ENU) ↔ PX4(NED) 변환
  - `NED_x = world_y`, `NED_y = world_x`, `NED_z = -world_z`
- 시간 동기: 두 로그를 단일 클록으로 기록 (안 하면 오프셋만큼 가짜 오차)
- 처리 지연 0.2초는 이동 중에만 오차로 나타난다(1.5m/s × 0.2s ≈ 0.3m). 채점은
  호버 시점 위치로 하므로 영향 없음 — 평가 기본값은 지연 보정 없이 둔다

## § 4. 시스템 전반 고려사항 (횡단 관심사)

**목적**: 위 3개가 나쁜 조건·실제 환경에서 안 무너지게.

- **4.1 강건성** — 비/안개 산란 노이즈(SOR 비활성 상태), 정적/동적 장애물 오검출,
  가림(occlusion), 추적상실 복구(코스팅→리셋)
- **4.2 실시간성** — 10Hz 유지. 128ch×2 = 프레임당 12만 점이지만 ROI z-band가
  대부분을 즉시 걷어내 부하는 낮다
- **4.3 캘리브레이션** — 센서 실제 설치위치 정밀도 = 측위 정밀도. **pose 오차가
  그대로 편향이 된다** — 실제로 params의 센서 좌표가 world와 9.8m 어긋났을 때
  검출률이 0%가 된 사례가 있다(에러 없이 조용히 실패하므로 원인 파악이 어렵다)
- **4.4 관측성 한계** — 기하학적 약점 인지 (Z축 약함, 근접면 편향 → ns 배치로 완화,
  실측 잔여 편향 0.048m)
- **4.5 초기화·실패모드** — cold start(home 씨딩), 오검출·드리프트 대응

## 설계 일관성 (한눈에)

```
①배치(ns, 2.0m, 128×2)  →  ②알고리즘(5단계)  →  ③평가(센트로이드·정밀도)  →  ④실전 대비
   입력 품질                  몸통: 위치 생성       내 스펙 + 정밀도 판단          강건·실시간·캘리브
```

**핵심 연결고리**: ns 배치(§1) → 양면 평균 → 센트로이드가 진짜 중심(§3.1) → 형상 무관 공정성.
①(배치)과 ③(기준점)이 서로 맞물려 돌아간다.

**대가도 맞물린다**: 좁은 수직FOV → 센서높이를 호버고도에 맞춤(§1) → 지상 관측
포기 → 패드 기준 캘리브레이션 불가(§3.2). 한쪽을 풀려면 다른 쪽도 다시 봐야 한다.
