# 칼만필터 적용 방식 — 현재 구조와 개선안

지상 LiDAR 2대로 드론 위치를 추정할 때 칼만필터를 어디에, 어떤 정보로
적용하고 있는지 정리하고, 측정을 근거로 개선안을 제시한다.

---

## 1. 현재 구조

### 1.1 전체 흐름

```
LiDAR1 ─┐  (비동기 수신, 각자 월드좌표 변환 후 버퍼에 최신값만 보관)
        │
LiDAR2 ─┘
        ↓  10Hz 타이머
   ① 신선도 검사   수신 후 0.25초 넘은 버퍼 제외 (센서 두절 판정)
   ② 동시성 검사   두 스캔의 촬영 시각 차이 50ms 이내만 융합
        ↓
   ③ 점 융합       두 포인트클라우드를 이어붙임 (np.concatenate)
        ↓
   ④ ROI 필터      XY: 필드+2m,  Z: 1.0~3.0m (호버 고도 밴드)
        ↓
   ⑤ DBSCAN        eps 0.40m, min_points 2
        ↓
   ⑥ KF predict    등속도 모델로 0.1초 전진
        ↓
   ⑦ 연관          예측 위치에 가장 가까운 클러스터 선택 (게이트로 거부 가능)
        ↓
   ⑧ 클러스터 median = 관측 위치
        ↓
   ⑨ KF update     관측으로 예측을 보정
        ↓
   /drone/estimated_pose
```

### 1.2 자주 하는 오해 두 가지

**"신뢰성 평가 후 융합한다"** — 현재는 하지 않는다. ①②는 *신선도*(센서가
살아 있는가)와 *동시성*(같은 순간의 스캔인가)만 본다. 관측의 *신뢰도*를
평가해 반영 비율을 조절하는 단계는 없다. 이것이 §3 개선안의 핵심이다.

**"칼만필터로 위치를 예측한다"** — 예측만 하는 것이 아니다. predict(모델로
0.1초 뒤를 추정)와 update(관측으로 그 추정을 보정)가 매 프레임 한 쌍으로
돈다. 예측은 관측이 끊긴 구간을 메우는 역할이고, 정상 구간에서는 update가
결과를 좌우한다.

### 1.3 융합이 일어나는 층위

두 LiDAR는 **점 층위에서 합쳐진다**(③). 합친 뒤에는 어느 점이 어느 센서에서
왔는지 구분하지 않으므로, 클러스터링·중심 계산·칼만필터는 **센서가 두 대라는
사실 자체를 모른다.** 필터 입장에서는 매 프레임 "위치 관측 하나"가 들어올
뿐이다.

이 구조의 장점은 한 센서가 일시적으로 가려져도 다른 센서의 점만으로 클러스터가
유지된다는 것이다. 단점은 §2에서 다룬다.

## 2. 현재 구조의 문제

### 2.1 측정 잡음 R이 고정되어 있다

```python
self.R = np.eye(3) * meas_noise_pos**2     # meas_noise_pos = 0.15, 생성 시 1회
```

관측 조건이 프레임마다 크게 다른데도 항상 같은 값을 쓴다.

| | 실측 범위 (1107프레임) |
|---|---|
| 클러스터 점 개수 | 2 ~ 55개 (중앙 12개) |
| 드론–센서 거리 | 5.4 ~ 15.7m (중앙 11.6m) |

점 2개로 잡은 중심과 55개로 잡은 중심을 **같은 신뢰도로 취급**하고 있다.

### 2.2 가중치가 암묵적으로 결정된다

명시적 가중치가 없으므로, 점을 많이 공급하는 센서가 median 계산을 지배한다.
각 LiDAR는 자신을 향한 면만 관측하므로 중심이 그 센서 쪽으로 치우친다.

실측 편향: **진폭 0.048m** (센서 점유율과 y오차의 상관계수 −0.248).
총 수평오차 RMSE 0.095m의 절반 수준이며, 채점 기준 0.5m의 10% 이내다.

## 3. 검토한 개선안과 검증 결과

### 3.1 (기각) 센서별 KF 갱신 + 편향 보정

**구상**: 센서별로 중심 c1, c2를 따로 구하고, 각각의 편향 δ를 빼서 KF를
두 번 갱신한다. 센서별 R로 가중을 명시한다.

관측식을 `h(x) = p + δ·û(센서 방향)`로 두어, 필터가 "이 센서는 원래 이만큼
치우쳐 찍힌다"를 알고 그만큼 감안해 비교하게 만드는 방식이다.

**기각 사유 — δ를 관측할 수 없다.** 구현 후 실측 검증 결과:

| 검증 항목 | 결과 | 필요 조건 |
|---|---|---|
| 양쪽 센서 동시 확보 | **60%** 프레임 | 높을수록 좋음 |
| 두 센서를 보는 방향 사이 각도 | 중앙 **95°** | **180°**(정반대) |
| 측정된 δ | **0.019 ± 0.041m** | 산포 < 값 |
| δ가 음수로 나온 비율 | **32%** | 0% (물리적으로 양수) |

`(c2−c1)/2 = δ`가 성립하려면 두 센서가 드론을 정반대에서 봐야 한다. 그런데
ns 배치에서도 드론이 필드 구석에 있으면 두 센서가 같은 쪽에서 비스듬히 보게
되어, 실측 각도가 중앙값 95°(거의 직각)로 나온다. 이 조건에서 두 중심의
간격은 δ가 아니며, 실제로 산포(0.041)가 값(0.019)의 2배이고 3분의 1이
음수로 나온다.

즉 **효과가 미미한 것이 아니라 전제가 성립하지 않는다.** 구현체는
`lidar_drone_tracker_fusion.py`로 남겨두었다(`per_sensor_update:=false`로
기존 동작과 동일해짐).

### 3.2 (채택) 관측 신뢰도에 따른 R 조정

**구상**: 센서 분리 없이, 융합된 클러스터 하나에 대해 관측 조건으로부터 R을
계산한다. δ가 필요 없고, 한쪽 센서만 보여도 동작한다.

```python
r = base + per_point / √(점 개수) + per_metre × 거리
```

점이 적을수록 중심이 흔들리고(≈1/√n), 멀수록 각분해능 때문에 같은 점 수라도
실제 산포가 커진다는 두 항을 더한다.

**검증 결과 — 위치 정확도는 개선되지 않는다.**

| R 설정 | 평균 | RMSE | P95 | 최대 |
|---|---|---|---|---|
| 고정 0.15 (현재) | 0.201m | 0.224m | 0.352m | 0.428m |
| 적응형 (점 개수) | 0.202m | 0.225m | 0.352m | 0.430m |
| 적응형 (점 개수+거리) | 0.200m | **0.223m** | 0.351m | 0.422m |

R을 0.108~0.310으로 3배 폭 변화시켰으나 RMSE 차이는 0.001m다.

원인은 칼만이득의 민감도에 있다. 프로세스 잡음 Q(0.05)가 작아 필터가 예측을
많이 신뢰하는 구조이므로, R을 3배 키워도 관측 반영 비율이 37%→15%로 바뀔 뿐
최종 위치는 거의 그대로다.

| R | 수렴 후 칼만이득 | 관측 반영 |
|---|---|---|
| 0.108 | 0.368 | 37% |
| 0.150 | 0.282 | 28% |
| 0.310 | 0.149 | 15% |

**그럼에도 채택하는 이유는 정확도가 아니라 공분산의 정직성이다.**

현재는 점 2개로 잡은 위치와 55개로 잡은 위치를 같은 공분산으로 보고한다.
이는 두 곳에 영향을 준다.

1. **`/drone/estimated_pose`의 covariance 필드** — 채점기나 후속 노드가 이
   값을 신뢰도로 사용한다면 잘못된 정보를 주게 된다.
2. **적응형 연관 게이트** — 게이트 폭을 KF 공분산에 비례해 넓히도록 되어
   있는데, 공분산이 실제 관측 품질을 반영하지 못하면 게이트도 엉뚱하게
   움직인다.

## 4. 구현 계획

### 4.1 변경 범위

`KF6D.update()`가 프레임별 R을 받을 수 있게 하고, 호출부에서 관측 조건으로
계산해 넘긴다. 센서 분리도, δ 추정도 필요 없다.

```python
# KF6D
def update(self, z, r=None):
    R = self.R if r is None else np.eye(3) * r ** 2
    ...

# 호출부 (_apply_measurement)
r = self.mn_base + self.mn_per_point / max(n_pts, 1) ** 0.5 \
    + self.mn_per_metre * dist_to_nearest_sensor
self._kf.update(centroid, r)
```

### 4.2 추가 파라미터

| 이름 | 기본값 | 의미 |
|---|---|---|
| `meas_noise_base` | 0.04 | 거리·점 수와 무관한 하한 |
| `meas_noise_per_point` | 0.25 | 점 개수 항 계수 (1/√n) |
| `meas_noise_per_metre` | 0.006 | 거리 항 계수 |

기존 `meas_noise_pos`는 세 값이 모두 0일 때의 고정값으로 남겨, 파라미터만으로
현재 동작을 그대로 재현할 수 있게 한다.

### 4.3 검증 방법

정확도 변화가 거의 없다는 것이 이미 확인되었으므로, 검증의 초점은 **공분산이
관측 조건을 따라가는지**에 둔다.

1. `/drone/estimated_pose`의 covariance를 점 개수·거리와 함께 기록
2. 점이 적은 프레임에서 공분산이 실제로 커지는지 확인
3. 적응형 게이트 폭이 그에 따라 넓어지는지 확인
4. 경로점 오차·검출률이 기존과 동일한지 확인(회귀 없음 확인)

## 5. 요약

| | 현재 | 개선안 |
|---|---|---|
| 융합 층위 | 점 (concatenate) | 동일 |
| 관측 개수/프레임 | 1개 | 동일 |
| 측정 잡음 R | 고정 0.15 | 점 개수·거리로 계산 |
| 가중치 결정 | 점 개수가 암묵적으로 | 동일(위치), R이 명시적(공분산) |
| 기대 효과 | — | 정확도 변화 없음, 공분산 정직성 확보 |

센서별 KF 갱신은 이론적으로 타당하나 **δ를 관측할 수 없는 기하 조건** 때문에
현 배치에서 성립하지 않는다. 배치를 정반대(두 센서가 드론을 180°로 마주보는
구성)로 바꾸거나 센서를 늘리면 재검토할 수 있다.
