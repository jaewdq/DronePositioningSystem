## 0. 한 줄 메시지 (발표 전체를 관통하는 주장)

> "팀마다 다른 기체를 **형상 무관하게**, 지상 고정 LiDAR 2대만으로 실시간 3D 측위한다 — GPS/온보드 센서 없이도 outside-in 방식으로 가능하다."

발표 마지막까지 이 문장을 뒷받침하는 근거(배치 설계 → 알고리즘 → 정량 결과)로 구성.

## 1. 제안 구성 (구두발표 15~20분 기준, 슬라이드 약 12~15장)

### ① 문제 정의 (1~2장)
- 배경: 실내 조난자 탐색 임무 — GPS 불가 환경에서 대회 참가팀들의 **서로 다른 기체**를 공정하게 측위/평가해야 하는 과제
- 왜 outside-in인가: 온보드 센서 의존 시 팀마다 성능 편차 → 형상/센서 무관한 "외부 심판" 필요
- 핵심 제약: 안전여유 33×23m 금지구역 밖에 센서 설치, 대회 지정 센서(Ouster OS0-SR)

### ② 시스템 개요 (1장)
- 데이터 흐름 다이어그램 1장으로: `LiDAR 2대 → 융합 → 전처리 → 탐지 → 연관 → 추적 → 출력 → 평가`
- README의 파이프라인 다이어그램을 그래픽으로 재구성해서 사용 가능

### ③ 센서 배치 설계 (2~3장) — DESIGN.md §1
- 왜 높이 1.5m인가 (2m와 성능 동일, 바닥 여유만 더 큼) — 표/그래프 1장
- 배치 4종(ns/cross/edge/diag) 비교: 검출밀도 점수(1600/거리²) 근거로 ns가 이론적 1위라는 결론 — 막대그래프 또는 필드 위 커버리지 히트맵
- **주의**: 현재 구현은 diag 배치. "이론적 최적(ns) vs 실제 검증(diag)" 관계를 발표에서 명확히 할 것 — 남은 과제로 자연스럽게 연결됨

### ④ 측위 알고리즘 (3~4장) — DESIGN.md §2 / `lidar_drone_tracker.py`
- 파이프라인 5단계를 시각적으로 (전처리→DBSCAN→연관→EKF)
- 실제 포인트클라우드 스크린샷/RViz 캡처 (있다면 강력한 시각 자료)
- 강조할 설계 디테일 2가지:
  - 지면제거 이중 가드(인라이어 비율 + 평면법선 수직성) — 왜 필요한가
  - home-seeding + 1.5m 게이트 — 바닥 스냅 방지 원리 (그림으로: "게이트 없으면 EKF가 바닥 잔여물로 떨어짐")

### ⑤ 평가 기준 및 방법론 (2장) — DESIGN.md §3
- "드론 위치 = 포인트클라우드 센트로이드" 정의와 그 이유 (형상 무관성) — 이 프로젝트의 철학적 핵심, 청중 설득 포인트
- 절대오차가 아니라 **정밀도(std)**를 핵심 지표로 삼는 이유
- 평가 파이프라인: `flight_recorder` → `plot_flight`의 시간정렬(±30s 탐색) + median/RMS/Z bias 계산 방법

### ⑥ 결과 (2~3장) — 가장 중요, 실측 데이터로 채워야 함
- README에 이미 있는 표: 경로점 수평오차 median ~0.1m (기준 <0.5m) 등 — **최신 수치로 갱신해서 사용**
- 궤적 오버레이 플롯(`plot_flight.py` 산출물: 계획 vs 실제 vs 추정) — 시각적으로 가장 설득력 있는 슬라이드
- 가능하면: diag 배치 실측 검출률 vs 설계서 이론값(9.0/26.2m) 비교 — "이론과 실측이 맞았는가"

### ⑦ 한계 및 향후 과제 (1~2장) — 정직하게, DESIGN.md "남은 과제" 그대로 활용
- ns 배치 실측 검증 미완료
- Z축 관측성 약함 (기하학적 한계)
- 추적 상실 후 재획득 로직 부재 (장시간 미검출 시 게이트에 막혀 재추적 실패 가능) — 코드 분석 중 발견한 항목, 발표 전 고치면 더 좋고 못 고치면 "알려진 한계"로 정직하게 언급
- 강건성(비/안개) 미검증

### ⑧ 결론 (1장)
- 한 줄 메시지 재확인 + 기여 요약(형상무관 정의, 배치 설계 근거, 실시간 파이프라인, 정량 검증 방법론)

## 2. 발표 전 우선순위 작업 (7주 남음, 오늘 2026-07-29 기준 9월 중순까지)

결과 슬라이드(⑥)가 발표의 설득력을 좌우하므로, 시간이 부족하면 아래 순서로 우선순위를 두는 걸 추천:

1. **가장 중요**: 현재 diag 배치로 실제 비행 로그 확보 → `plot_flight` 오차 통계를 발표용 최신 수치로 갱신
2. Z축 편향/std를 별도로 명시 (설계서 §3.2 "정의 차이 vs 오차" 구분을 결과 해석에 반영)
3. 시간 되면: ns 배치도 한 번 더 실측해서 diag와 비교 슬라이드 추가 (이론(§1) 검증 스토리가 완성됨 — 학회 발표에서 강한 임팩트)
4. 여유 있으면: 추적 상실 재획득 로직 보강 (지금은 "한계"로만 언급해도 발표에는 무방)
